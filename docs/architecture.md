> 2026-11-13 确认定稿（闸门确认记录见 `plan/gate_architecture.html`）。
> 一句话：**脑说内容，体做动作，场给舞台，MCP 当神经**。

## 0. 已确认的决策

| 决策点 | 结论 |
|---|---|
| 架构总览 | 脑·智库 / 体·载体 / 场·DEMO 三位一体，按图确认 |
| DEMO 形态 | **A 桌面地图垫 + 站点动线**（纯导览，不做集章游戏） |
| 智库 API | 交由技术侧定 → **静态导出挂上海 VPS**（理由见 §3） |

## 2. 体 · 载体——能力边界（本架构最重要的一段）

**没有摄像头、舵机无反馈（开环）**，意味着：

- ❌ 不做：自主导航、走到指定站点、避障、循迹
- ✅ 只做：**定点讲解为主，短距串场为辅**
  - 科鲸站在地图垫「主场位」，每讲一站：**转身朝向站点 → 举旗/招手动作 → 屏幕表情 → 讲解**
  - 站与站之间偶尔 `walk_short`（几步开环小碎步）+ `turn` 制造「带路感」，不承诺停在哪
- 动作全部来自固件已有原语（walk/turn/jump/swing/moonwalk/laugh），零固件改动
- **Phase 2 接口**：决策层下发动作时附带 `target_station` 字段（v1 固件忽略之）；将来感知层接入后，动作层拿这个字段做闭环。接口留好，一行不改就能升级

## 3. 脑 · 智库——出口方案（已定：静态导出 + 上海 VPS）

**为什么不用穿透回 mini**：演示当天家里断电/断网/mini 休眠都是单点故障，且 tailnet 实测走 DERP 香港中继（~290ms）不稳定。
**为什么选静态导出**：查询逻辑简单（ask.py 就是打分检索），数据 212 卡导出后 <1MB，VPS 上一个极薄 HTTP 服务即可，家里 mini 挂了也不影响现场。

```
mini（生产）                    上海 VPS（服务）              xiaozhi.me（消费）
datawhale-wiki/  --build.py-->  data/*.json + /query API  <-- guide_query MCP
   改卡 → 一键部署脚本 deploy.sh --------推送-------->  systemd 常驻
```

- 部署目标：shanghai-vps（111.229.200.105，腾讯云上海，离会场最近）
- 兜底梯子：① VPS API 挂了 → ② 人设内置兜底话术 + 现场 booth.html（iPad 断网页兜底）→ ③ 纯动作演示
- 智库权限闸门延续：`pending-auth / internal-only` 卡**不进** VPS 导出物（build 已保证）

## 4. 场 · DEMO——地图垫动线（保持简单）

- **地图垫**：A2 单张打印（淘宝，随壳一起下单），画面 = Datawhale「版图」：6 个站点 + 主场位 + 路径虚线
  - 站点：①起点 2018（成立）②开源教程 ③组队学习 ④AI+X 碰头会 ⑤高校行 ⑥认证与竞赛
- **站点小立牌** ×6：折纸立卡或 3D 小件，印站点名（备打印）
- **体验主线（3 分钟）**：
  1. 游客说「开始导览」/按 BOOT → 科鲸欢迎语 + 举旗
  2. 沿站点逐个：转身 → 讲解（每站 20–30s，词全部来自智库卡）→ 表情
  3. 结束语 → 进入自由问答（guide_query 实时查智库）
- 游客问路交互：「XX怎么走」→ 科鲸转向 + 指方向 + 举旗（预录方位话术，不真走）

## 5. 编排层——route.json（新增的唯一开发产物）

```json
{
  "stations": [
    {
      "id": "s1_origin",
      "name": "起点·2018",
      "say": "…（来自智库 org-datawhale 卡）",
      "actions": ["wave"],
      "screen": "happy",
      "sources": ["org-datawhale"]
    }
  ],
  "transitions": [
    { "from": "s1_origin", "to": "s2_courses", "actions": ["walk_short", "turn_left"] }
  ]
}
```

- 写作流程：从智库挑卡 → 摘成 30s 口播词 → 配动作表情 → 存 `route/route.json`
- 消费方式：xiaozhi 人设系统提示词里写死导览主线的站点顺序与触发词，讲解词进人设知识库（或 guide_query 按 station id 取）
- **route.json 同时是 Phase 2 感知层的输入**：闭环时按 transitions 的目标位做视觉校准
